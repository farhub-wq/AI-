# 业务流程说明


## 1. 客服问答主流程

```mermaid
flowchart TD
    A[用户登录] --> B[进入智能对话]
    B --> C[创建或选择会话]
    C --> D[选择知识库或自动路由]
    D --> E[输入问题 ≤500 字]
    E --> F[后端校验配额/权限]
    F --> G[意图识别]
    G --> H[向量检索 Top-K]
    H --> I{阈值过滤后是否有证据}
    I -->|否| J[SSE 兜底 fallback]
    I -->|是| K[证据分层打包]
    K --> L[LLM 流式生成]
    L --> M[数字一致性校验]
    M -->|失败| N[降级摘要 degraded]
    M -->|通过| O[citation + success]
    J --> P[展示意图/答案/引用]
    N --> P
    O --> P
    P --> Q[点赞点踩反馈]
    P --> R[追问建议点击]
```

## 2. 登录与会话

### 2.1 登录

1. 邮箱+密码或手机号+密码  
2. 后端校验并签发 JWT  
3. 前端保存 token，后续 REST/SSE 带 `Authorization`

### 2.2 会话

1. 侧栏拉取历史会话列表  
2. 点选会话加载完整消息（含意图标签、引用、状态）  
3. 新会话可指定 `kbId`；问答时 `kbId≤0` 触发多库自动路由  

## 3. 问答详细链路

### 3.1 前置校验

1. 提问长度 ≤ 500  
2. 当日提问未超 `DAILY_QUESTION_LIMIT`（默认 100）  
3. 会话归属当前用户  

### 3.2 后端处理时序

```mermaid
sequenceDiagram
    participant FE as ChatView/SSE
    participant CS as ChatService
    participant IC as IntentClassifier
    participant KB as KnowledgeBaseService
    participant EG as EvidenceGovernance
    participant LLM as OpenAiCompatibleChatClient

    FE->>CS: POST /chat/stream
    CS->>IC: classify
    CS->>KB: searchSupportChunks / 自动路由
    CS->>EG: pack(分层/去重/预算)
    alt 空证据
        CS-->>FE: token 兜底文案
    else 有证据
        CS->>LLM: streamAnswer(EvidenceBundle)
        LLM-->>CS: deltas
        CS-->>FE: event token
        CS->>EG: validateAnswer
    end
    CS-->>FE: citation / message_end
```

### 3.3 前端渲染

1. `message_start`：占位助手气泡，写入 `intentLabel`  
2. `token`：逐字追加  
3. `citation`：右侧/底部引用来源（文档名 + 摘要）  
4. `message_end`：开放反馈与追问按钮；展示 `answerStatus`  

## 4. 知识库入库流程

```mermaid
flowchart LR
    A[上传 multipart] --> B[落库 status=processing]
    B --> C[异步解析切块]
    C --> D[Embedding]
    D --> E[VectorIndex upsert]
    E --> F[status=ready]
    C --> G[失败则 failed]
```

增量语义：仅 upsert 新文档切块；删除文档时同步删除对应向量。不重建整库。

支持格式：`.txt` / `.md` / `.pdf`。

## 5. 反馈与运营

1. 用户对助手消息点赞/点踩并可填评论  
2. 写入 `message_feedback`  
3. 管理后台查看提问量、好评率、兜底率、低分问题

### 6.1 页面展示（已实现）

1. 变更单号 / 优先级 / 提出人  
2. 规划状态 `success/partial/failed`  
3. 受影响服务及理由 + 文档证据  
4. 本计划依赖边 + 全量依赖目录  
5. 可并行任务组  
6. 建议发布/合并顺序  
7. 任务 DAG：串行链（依赖显示为任务名，含负责团队/依赖类型）+ 可并行区  
8. 验证步骤、人工评审清单、缺失证据提示  
9. 历史规划下拉切换

## 7. 异常分支

### 7.1 检索为空

1. 不调用 LLM 编造细则  
2. `answerStatus=fallback`  
3. 引导补充商品/订单等上下文  

### 7.2 LLM 失败或一致性校验失败

1. 回退分层证据摘要  
2. `answerStatus=degraded`  
3. SSE 仍可输出完整保守回答  

### 7.3 文档删除

1. 删 MySQL 文档与切块  
2. 按 `vectorId` 删向量索引  
3. 列表刷新  

### 7.4 变更规划证据不足

1. `status=partial` 或 `failed`  
2. `missingEvidence` 列出缺失文档/校验项  
3. 评审清单提示补文档后再合入  

## 8. 联调检查顺序（摘要）

1. MySQL /（可选）Qdrant  
2. Embedding / Chat API  
3. 登录 → 上传/种子文档 ready  
4. SSE 问答有引用与意图标签  
5. 变更规划默认「下单发短信」拆解出并行/串行与发布顺序
